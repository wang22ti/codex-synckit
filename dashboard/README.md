# Memory Observatory

`memory-and-improvement` 的本地状态仪表盘。它默认只读取元数据；仅在用户
主动点击文件时从本机按需读取正文，不向外部服务传输 Memory 内容。

## 能看到什么

- 已注册的项目 Memory、存储类型、设备归属和当前可达性
- 全局 Memory 命名空间、条目数、文件数和最近活动
- SessionStart / UserPrompt Hook 状态
- 最近维护时间、注册表格式和重复项
- 系统健康分、异常提示、搜索与状态筛选
- 手动扫描受控根目录中的 `.learnings`，区分未注册、已注册、全局管理和同步副本
- 从最近活动或目录列表进入详情页，点击最近修改文件查看只读文本正文

“记忆目录”以项目注册表为完整底账，再叠加 Codex 侧边栏状态和全局命名空间；
同一个 `.learnings` 路径只显示一次，侧边栏信息优先用于补充项目名称和覆盖状态。
因此，手动加入注册表但尚未出现在 Codex 侧边栏的目录也会正常显示。
目录、规模、最近活动和状态四列表头均可点击排序；再次点击同一列表头可切换
升序与降序。

## 启动

需要 Node.js 22.13 或更高版本。

```powershell
npm install
npm run dev
```

然后访问 <http://localhost:3000>。页面每 60 秒自动刷新，也可以手动刷新。

当 `dashboard` 不直接位于私有 `CodexKit` 目录下时，请在启动前设置
`CODEXKIT_ROOT` 为该私有目录的绝对路径。公开源码仓库不包含任何私人 Memory
数据。

文件正文接口只监听 `127.0.0.1`，只允许读取当前记忆目录白名单中的常见文本
文件，并拒绝绝对路径、目录穿越和符号链接越界。单次预览最多读取 512 KiB，
Markdown 以纯文本显示，不执行其中的 HTML 或脚本。

在“记忆目录”页点击“扫描未注册记忆”可执行一次只读发现。默认扫描
OneDrive、Documents 和 Desktop；扫描根目录、最大深度、目录上限及排除项由
`../memory-system/discovery-roots.json` 控制。扫描不会自动修改注册表。
对确认需要保留的未注册候选，可逐条点击“加入注册表”；全局记忆和
CodexKit 同步副本不会提供该操作。`Documents\Codex` 工作目录与
`CodexKit\CodexProjects` 传输副本按相对路径视为同一个托管项目：
优先展示和注册本机工作目录，不重复展示对应的传输副本。

不需要的未注册候选可逐条点击“删除记忆”。操作需要二次确认，只移动
`.learnings`，不删除项目目录；内容会进入本机
`%USERPROFILE%\.local\state\memory-dashboard\removed-memory` 隔离区。
托管项目的工作副本和同步副本作为同一个逻辑单元一起隔离；全局记忆、
已注册记忆和孤立传输副本不会提供删除操作。

## 其他命令

```powershell
npm run status  # 在终端输出当前状态 JSON
npm run build   # 验证正式构建
npm test        # 构建并运行数据与页面测试
```

本地状态接口只监听 `127.0.0.1:4174`。由于它需要读取本机目录，本项目默认不部署
到云端。
